# /develop — 完整開發流程（v2）

> 這個系統是**思考機器，不是生產機器**。  
> 生產（劇本 → 成片）交給小雲雀或等效工具。  
> 這裡解決的是生產工具解決不了的問題：這個故事值不值得生產。

---

## 系統架構：三個思考模式

```
DESIGN（設計）←→ EXECUTION（執行）←→ DIAGNOSTIC（診斷）
```

可以從任意點進入。沒有強制線性順序——但有前置依賴。

---

## 設計模式（建構有效故事）

### Step 1：`/story-core`
**核心問題**：這個故事有沒有存在的理由？

- PREMIUM 入口：情感真相 + 角色創傷 + 情感差異化
- MARKET 入口：投流邏輯 + 爽點時機 + CPM 競爭分析
- 兩條路線共用：套路鎖定 + 差異化方向

**Gate 1**：STORY CLEAR 後繼續。STORY DEAD → 停止，不要生產。

### Step 2：`/story-architecture`
**核心問題**：這部劇的五個決定命運的時刻是什麼？

- 五個槓桿時刻（創傷暴露 → 錯誤應對 → 表面勝利/內在失敗 → 不可逆代價 → 直面或毀滅）
- 資訊建築圖（誰知道什麼，何時揭示，戲劇性功能）

**Gate 2**：ARCHITECTURE LOCKED 後繼續。這張圖是後續所有集數的查詢工具。

---

## 執行模式（寫好每一集）

### Step 3：`/episode`（循環執行）
**核心問題**：這一集在架構裡是什麼位置？它的情感交易是什麼？

- 查詢資訊建築圖 → 確認這集的資訊狀態變化
- 情感交易四格（承諾/交付/驚喜/欠債）
- Scene Spine 場景驗證
- Cliffhanger 三溫度（熱/冷/溫，不能連續重複）
- MARKET 路線：標注投流截取點

先寫 Block 1（第 1-10 集），驗證後繼續後續 Block。

---

## 診斷模式（找到問題根源）

### `/diagnose`（隨時可進入）
**核心問題**：故事從哪集開始失去動力？

三個根本原因診斷框架：
1. **Character Drift**：角色行動與核心創傷脫節
2. **Escalation Stagnation**：賭注沒有升級
3. **Information Collapse**：資訊不對稱已消解，沒有新的不對稱建立

診斷後輸出具體處方，回到對應的 Skill 修復。

---

## 精品升維（PREMIUM 路線限定）

### `/formula-break`（在 `/episode` 第一個 Block 完成後）
**核心問題**：在哪裡突破公式？突破多少是安全的？

MARKET 路線不需要這個步驟。

---

```
   ▼

   │

   │
   ├── PREMIUM 路線 → /formula-break
   │
   ▼
/episode（Block 2-5，繼續）
   │
   ▼
[交付生產工具]
```

## 這個系統不解決的問題

- 劇本 → 成片的生產問題（交給小雲雀）
- 視覺角色一致性（交給小雲雀）
- 投流策略和平台選擇（不在範圍內）
- 備案通過率（設計層面可降低風險，但不保證）
